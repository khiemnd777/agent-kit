# Using Agent Skills

Use the [lean operating core](../../../AGENTS.md). A skill supplies techniques for a current need; it does not add a lifecycle, permission or required agent.

## Select only what helps

Start from the requested outcome and relevant source. During planning, select minimum sufficient skills and state why they fit the task type, boundaries, risks and outcome. If ordinary project knowledge is sufficient, no extra skill is required; the plan still requires approval before implementation. Otherwise match the unresolved need to a description in the [catalog](../../../docs/skills-catalog.md), read that entrypoint, then open only the reference section needed for the decision. Return to the task when that need is resolved.

Do not preload every skill or chain specification, planning, implementation and review skills by default. A skill name in an example is not an invocation requirement. Use available tools and real skill paths; do not invent slash commands or missing skills.

## Report actual participation

At planning and implementation handoff, include only applied skills in one table: Skill | Source | Actual contribution | Estimated participation %. Use Personal / Repo; UNKNOWN if unverified. Estimates total 100% among applied skills and are not measured time/tokens or effectiveness. If none was used, say so. Keep paths/versions/fingerprints in the [journal](../../../docs/engineering/skill-usage/README.md); the owner saves authorized phase records before reporting and derives the table from them. Do not write during unapproved/read-only planning or duplicate usage on resume.

## Resolve ambiguity

When names collide, identify the effective source before relying on it. Preserve the project's stack, contracts and current scope; do not change global settings to force discovery. Resolve material instruction/authority conflicts through the applicable instruction hierarchy, consulting [policy](../../../docs/team-policy.md) only if needed.

The deliverable is the user's result or evidence-backed answer. Completing a skill sequence is not an acceptance criterion. Report meaningful checks and limits; source inspection does not prove native discovery or runtime behavior.
