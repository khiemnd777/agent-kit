For each actual task, index its ID, owner, role, branch, base commit, owned files, dependencies and task-record path. Detailed acceptance, evidence and handoff belong in the task record, not a duplicate checklist here.

Agree shared contracts and write ownership before parallel execution. A later task must not silently replace an unfinished task. Planning-only drafts may be saved from task start under the [core documentation permission](../AGENTS.md#planning-only-documentation), with proposals/open points explicitly marked. Saving a draft does not approve implementation; explicit read-only/no-file restrictions still apply.

## Delivery planning

Declare delivery type, rationale and parent roadmap at the start of the conversation plan using the [classification criteria](handoff-templates.md#classification); a saved table is not a substitute. For roadmap delivery, agree all meaningful packages in advance: IDs/names, outcomes, dependencies and observable acceptance. Keep the stable overall picture in project-context.md and live progress only in project-state.md.

Within each approved package, complete production code and real wiring before writing/updating and running tests, then verify and hand off. Stop until the user/Product Owner accepts that package and authorizes the next. Overall-roadmap approval alone does not cross the stops. One-handoff work is assessed together without invented phases. Risk-specific checks remain required for either type. These instructions do not populate this template or authorize execution.
