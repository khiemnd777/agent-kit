# TechNote

Present the technical result with enough evidence to support it. TechNote controls **explanation**, not implementation scope, approvals or agent stages. Default to the requested language and Level 1; a short standalone response needs no report form.

## Level 1 — Technical note

State the main result, meaningful evidence or limits, and the next action **only if work remains**. Keep simple answers short. Distinguish observed behavior, proposed choices and unknowns without mandatory labels; never claim runtime proof from source or a build. State actual checks and their results when relevant.

Omit unchanged context, generic status narration, empty fields, repeated approval references and logs. Use one [task checkpoint](tasks/README.md) for durable resumption rather than duplicating state in chat.

## Level 2 — Diagrams

When requested, show actors, data, actions and decisions in a supported diagram; label hypothetical/unknown behavior. A diagram is not runtime evidence.

## Level 3 — Interactive explanation website

When requested, deliver a functioning interactive explanation and check navigation, reset/replay and relevant viewports. Distinguish examples/simulations from observed behavior. Hosting needs authority.

## Level 4 — Explanation video

When requested and feasible, produce and check an actual exported video; a script is not a delivered video. No unauthorized publication or sensitive capture.

The user may select any level directly. Read the [optional extended method](technote-reference.md) only for deeper evidence rules, examples, website/video delivery or specific presentation requirements.
