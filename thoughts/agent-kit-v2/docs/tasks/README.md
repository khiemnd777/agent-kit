# Task records and resumption

A short authorized task can live in the conversation, source diff and result.
Use an existing task record or one checkpoint when continuity, coordination or
actual project policy needs it. Do not create a record per tool invocation.

Keep: outcome; scope/acceptance; actual approval reference; latest human stop;
completed/remaining work; material decisions; source/snapshot; actual evidence;
active execution request IDs if any; and the next action/blocker.

The delivery owner writes shared state. Children return proposed updates.
Planning-only documentation permission does not authorize code or runtime changes.
Never copy another project's approvals, client transcripts, secrets or success
records into a new project. On resume, compare relevant source/environment,
reuse unaffected evidence and respect remaining authority boundaries.
