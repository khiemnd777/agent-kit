# Security model — read before enabling process execution

## Supported trust model

This is a **single-user local execution tool**. The local user, reviewed Sidecar
source/dependencies, registry, policy and host are trusted. There is no remote or
multi-tenant server. Policy and permits are private files; the OS account is the
real principal. Another process with the same account can change those files.
A permit is a request-bound caller attestation, not a signature, human identity
check, privilege separator or approval generated by the executor.

Agent Kit/user authority must already exist. `--confirm-authorized` records that
existing authority; it does not create it. A release's `lifecycle: reviewed` or
`review_ref` is not permission to run on your repositories. Review then pin the
exact workflow digest in your policy. Do not let untrusted input author policy.

## Default: builtin-only work

Builtin checks read a sealed-by-convention, content-addressed snapshot through
contained paths. They do not execute project code, evaluate manifest commands,
load plugins from the target or call the network/LLMs. Input/output sizes are
bounded. Symlink and special-file inputs are rejected. Snapshots are verified
before and after execution. These controls are not an adversarial same-user
filesystem sandbox; a process with the same account can race or replace files.

## Opt-in: trusted local subprocesses

Process mode requires all of:

- a reviewed workflow digest explicitly allowed by the policy;
- pinned, available executable bytes;
- `allow_trusted_process: true` and the exact risk acknowledgement;
- actual scope authority and a current request-bound permit/caller confirmation.

Each step gets its own writable source copy and private HOME/temp directory. The
engine uses argv without an implicit shell, a minimal environment (no inherited
API credentials), process groups, deadlines, output ceilings and bounded retries.
It never intentionally edits the original worktree. These are useful containment
and reliability measures, **not OS-level security isolation**.

**A child process can access the host filesystem and network using its OS account.
It can escape a process group, fill disk, use memory/CPU, invoke other programs or
modify files it can find. Sidecar cannot enforce a filesystem/network allowlist in
this mode.** Executable fingerprints do not pin transitive tools, libraries or
external services. Do not run hostile code, unknown PRs, credentials, customer data,
production operations or a workload requiring hard isolation. Use an independently
authorized host/container sandbox or wait for a future isolated executor.

The V1 contract profile rejects network and original-source-write effects. In process
mode, those are obligations of trusted code and its host, not kernel-enforced claims.
A cancellation, timeout, signal termination, escaped/background-child symptom or
unsettled output reports **unknown effects** and requires reconciliation. Killing
a process group is not evidence that all possible external effects rolled back.

## Credentials, artifacts and retention

Snapshot filters exclude common `.env`, key files, Git metadata, virtual environments,
node_modules and caches. Exclusions are disclosed. This is **not a secret scanner**;
secrets can exist under arbitrary names. Inputs, argv, policy and approval references
must not contain credentials. Snapshots, logs and private working copies can contain
source/private data; state must be mode 0700, files are written mode 0600.

No automatic upload or telemetry occurs. Logs are retained locally without semantic
secret redaction; summaries do not echo raw subprocess logs. Do not upload the runtime
state directory as part of a source repository. Cleanup is explicit operator work
when no run is active; there is no retention daemon or silent deletion.

## Evidence is not authentication

Artifact hashes detect accidental/tampered content relative to the result. They do
not authenticate a malicious result creator. Validate request identity, exact checks,
workflow/source/environment/policy pins and actual artifact bytes. Treat artifact
text as untrusted data, never instructions to grant permission or expose secrets.
Human acceptance and release are not result fields.
